## Bounded native bulk capacity diagnosis

The provider-facing `ParsedProcurementRequest` schema was accepted on synthetic native extraction. An eight-row, 742-byte fixture at `high` effort completed in 33.72 seconds; a prior same-size call completed in 28.03 seconds. A 48,254-byte, 55-row fixture then completed in 224.316 seconds at `high` with the 300-second cap. It returned all 55 distinct codes, exact quantities and source units, all 10 top-level fields and 495 item scalar fields explicitly, and passed schema, binding, and the existing 65,536-byte result cap. Stream aggregates showed one thread start, one turn start, one agent-message item completion, one successful turn completion, no error or retry events; auth-file metadata was unchanged. Earlier full-size calls timed out at 180 seconds at both xhigh and high; the later 300-second success shows the earlier timeout was duration-bound for this fixture rather than a schema rejection. This verifies one representative 55-row payload, not an SLA or all document shapes.

Keep the default provider timeout at 45 seconds and allow an explicit bounded setting up to 300 seconds. Do not change default reasoning effort or raise the 65,536-byte result cap without output-size evidence. The worker renews its 300-second job lease every at most five seconds, cancels dispatch on ownership loss, and `_run_cli` terminates/drains the process group on cancellation or timeout. Existing worker and subprocess cancellation tests cover these boundaries. The 55-row probe passed within the explicit cap; no further live retries are needed.

For future documents larger than the current single-call input cap, use existing `DocumentSegment` boundaries in `documents.py`: PDF pages, DOCX paragraphs, and DOCX table rows already carry stable locators and order. Form deterministic chunks only between source segments, respecting per-input byte/character caps; never split a table row. Keep the original complete document text and its hash as the immutable parent source. Each chunk manifest should bind ordered original locators, chunk bytes/hash, whole-document hash, current request, and intake spec hash. Extract page/row facts using the existing reviewed native request model, attach original locator references to every fact, then merge by original segment ordinal and in-segment order without inventing or rewriting source identifiers. Combine request-level fields only when consistent; preserve conflicts as ambiguities, keep unknown quantity/unit/price/currency values null, and retain warnings/ambiguity flags. Overlapping windows need deduplication only by exact source locator and fact identity; fuzzy name-based merging could erase distinct rows. Keep the existing canonical whole-message context binding for application writes, and validate every chunk binding before merging. Oversized indivisible segments must fail safely or use a separately reviewed deterministic subsegmenter with offsets; no generic arbitrary-model chunking layer is approved.
