снижает неподтверждённый статус наличия до `unknown`.

## Тест WhatsApp владельцу

Одобренное сообщение владельцу было поставлено в outbox на 09:01 Алматы.
Первый вызов WAHA завершился HTTP 422: сессия `default` оказалась в `FAILED`.
Штатный `POST /api/sessions/default/restart` вернул `STARTING`, затем сессия
перешла в `WORKING`. После повторной обработки `sendText` принял запрос,
но HTTP-ответ не содержал ID сообщения; адаптер ошибочно счёл это отказом.
Две попытки использовали один заранее зарезервированный ID. История WAHA
показывает ровно одно исходящее сообщение с этим ID и точным одобренным текстом.

Адаптер теперь использует зарезервированный ID для успешного `sendText` без ID
в ответе и классифицирует HTTP 422 при резервировании ID как временную
неготовность сессии. Изменение прошло 26 тестов блока WAHA/outbox. Уже
существующее сообщение согласовано с outbox и журналом диалога без нового
вызова `sendText`: `outbox=sent`, одна запись исходящего сообщения,
`outbound_count=1`. На момент последней проверки WAHA показывает
`ackName=PENDING`; доставку на устройство это не подтверждает.

Одна задача `prepare_supplier_outreach` завершилась с `dead`, пока сессия WAHA
была в `FAILED`. После восстановления сессии та же идемпотентная задача
повторно поставлена в очередь и завершилась успешно: проверен ещё один номер,
WhatsApp подтверждён, черновик подготовлен. На 25.09.2026 10:21 Алматы
`procurement-bot health` вернул `ok`: 59 завершённых задач, 0 мёртвых,
37 отправленных событий outbox. Пилотная заявка в `report_ready`, текущий
отчёт v15. В ней 132 предложения по четырём позициям (33/34/33/32), но
`exact_matches=0`, поставщикам по пилоту сообщения не отправлялись.
Ожидают решения 15 запросов `send_whatsapp`; одобренный тест владельцу учтён
отдельно и не означает подтверждённой доставки на телефон.

Последний прогон Armstrong через OLX завершился ошибкой сохранения до
исправления связи OLX seller ID с существующим телефонным контактом. Исправление
проверено кодом и SQL с откатом, но живой повторный прогон остаётся открытым:
фоновый Chrome пока не подтверждён в нужном аккаунте OLX. Флаг OLX fallback
на сервере выключен до этой проверки. Итоговая выборка тестов изменённых
путей: 51 passed, 1 skipped; `compileall` прошёл.

После очистки старых вкладок серверный Codex смог открыть новую вкладку OLX,
но увидел форму входа: существующей открытой вкладки OLX не было. В OLX
fallback добавлено требование подтвердить вход по видимому интерфейсу;
для этого он может открыть свежую вкладку в подключённом Chrome. При форме
входа или недоступном интерфейсе возвращает `login_wall` без кандидатов.
Это не меняет AGY как основной источник и не включает fallback
автоматически. Проверка кода провайдера: 13 тестов прошли.
