# Готовность procurement bot к продакшену — 24.09.2026

## Вердикт

Сервис пригоден для ограниченного пилота с владельцем, ручной проверкой
результатов и действующими approval gates. **Полная архитектура ещё не
готова к самостоятельной промышленной эксплуатации.** Запущенные процессы
и успешные unit-тесты подтверждают работоспособность основы, а не всех
сквозных сценариев.

## Что блокирует статус «готово по всей архитектуре»

1. **Нет подтверждённого end-to-end запуска на реальной заявке.**
   База не содержит активных позиций или предложений. Нужно пройти
   Telegram → intake → уточнение → research → предложения → approval →
   WhatsApp → ответ → оценка → отчёт, проверяя события и ошибки на каждом шаге.
   Сама WAHA-сессия активна, но это не доказывает корректность всего сценария.
2. **Telegram dialogue/outbox backlog не реализован.**
   В `REMOTE_AGENT_TASK.md` описаны immutable ledger исходящих сообщений,
   `DialogueContextRepository`, безопасное переключение нескольких заявок
   и полный каталог RU/KK ответов. Нет миграции 013 и интеграционных
   проверок этих контрактов.
3. **Notion не интегрирован с текущей БД.**
   Историческая карта есть в `docs/notion-maxim-structure.md`, но живая
   схема не сверена, импорт и idempotent page-ID mapping отсутствуют.
4. **Восстановление после сбоев не доказано.**
   Outbox имеет at-least-once семантику; crash после отправки provider API
   и до DB commit требует reconciliation. В репозитории не найден
   воспроизводимый backup/restore runbook PostgreSQL с проверкой
   восстановления.
5. **Интеграционные проверки неполные.**
   Два PostgreSQL теста пропущены без `TEST_POSTGRES_DSN`; live
   Playwright/2GIS executor включён конфигурацией, но в README нет
   подтверждённого внешнего smoke-test конкретного MCP профиля.

## Остальная граница продукта

Согласно `README.md`: OCR фото/сканов и чеков отсутствует; входящие
WhatsApp media replies не обрабатываются; многострочный initial outreach
одному поставщику ограничен; recommendation set не персистится. Это
ограничения для полной целевой архитектуры, хотя узкий пилот с ручной
проверкой возможен.

## Условия для следующего решения о релизе

1. Утвердить модель доступа: участники видят общие заявки или только
   собственные. Затем добавить роль/членство в БД и проверить изоляцию
   всех Mini App запросов.
2. Реализовать и проверить `REMOTE_AGENT_TASK.md` на одноразовой
   PostgreSQL БД, затем применить новую миграцию на рабочем сервере.
3. Подключить Notion, сделать dry-run импорта и сверку дубликатов.
4. Провести сквозной сценарий на новой заявке с человеком на точках
   approval; проверить live browser research, WAHA reply и отчёт.
5. Добавить резервное копирование, тест восстановления и процедуру
   reconciliation неоконченных исходящих событий.

Нельзя использовать текущий `procurement-bot health` или статус WAHA
`WORKING` как единственный сигнал готовности сценария закупки.
