# UranEnergo integration scout — 2026-10-18

## Recommendation

Keep the existing Python/PostgreSQL/Redis, Telegram intake, Mini App, WAHA, AGY/browser and supplier dialogue pipeline as the application. The project already has durable jobs, evidence, supplier/offer records and outbound controls. The immediate gap is to validate the current end-to-end path and its live state, not to replace it with an agent framework.

For PDF/DOCX, compare today's built-in PyMuPDF/python-docx extraction with a small isolated [MarkItDown](https://github.com/microsoft/markitdown) trial first. Trial [Docling](https://github.com/docling-project/docling) only against a representative sample where tables, layout or scans defeat the current parser. For the model step, retain the app's existing Pydantic schema and AGY/LLM boundary; use [Instructor](https://github.com/567-labs/instructor) as a focused comparison only if the existing adapter cannot reliably return validated structured rows. Do not add a workflow framework or a web crawler to the live worker as part of recovery.

This is a shortlist of candidates, not an instruction to install dependencies. Repository pages and license files were checked on 2026-10-18. Maintenance signals are GitHub's visible release/activity/commit history on that date; they are not a guarantee of support.

## Small, reviewable experiment

Use a fixed, redacted set of existing PDF and DOCX test fixtures that cover born-digital PDFs, scanned pages, Cyrillic text, tables, units, quantities, prices, delivery terms and multi-page lists. Run the current parser and one candidate offline. Compare extracted text, row/column preservation, exact numeric values, provenance/page references, wall time, peak memory and installation footprint. Keep persisted output outside the live database until an owner reviews the row mapping.

If the current stack already meets the 55-line baseline, retain it. If only scans fail, test an OCR-only fallback. If complex layout fails, compare Docling in a bounded child process. Add no new service or orchestration dependency unless that measured trial identifies a narrow gap.
