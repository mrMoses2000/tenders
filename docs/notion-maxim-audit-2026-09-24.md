## Универсальная модель исполнения позиции

Для школы, производства, предприятия и другого заказчика нужен набор
независимых состояний. Один общий текстовый статус теряет частичные
количества и допускает противоречия.

| Ось | Состояния | Источник истины |
| --- | --- | --- |
| Поиск и выбор | нет лидов → лиды → проверка → выбран вариант / нет совпадения | предложения и наблюдения с URL, датой, техспеком |
| Закупка | не закуплено → частично → полностью | строки закупки и документы |
| Перемещение | не отправлено → склад → частично у заказчика → доставлено | отдельные события количества и местонахождения |
| Приёмка | ожидает → принято частично → принято полностью | акт / подтверждение заказчика, количество |
| Исключения | отклонено, на замену, возвращено, отменено частично или полностью | отдельные события с причиной и доказательством |

Минимальные инварианты: известные количества неотрицательны; принятый плюс
отменённый объём не превышает требуемый; отмена не стирает закупки и
историю поставки; возврат и замена записываются новыми событиями;
неизвестное количество остаётся `NULL`. Повтор сообщения не создаёт
повторное событие. Для каждого расхождения между источниками показывается
«требует сверки» с объяснением, а не искусственно окончательный статус.

Управленческая сводка должна показывать одновременно:
`требуется / закуплено / передано заказчику / принято / отклонено /
отменено / остаток к приёмке`. Для импортированной Караганды отдельно
показывать `по Notion` до подтверждения событиями. Скрываемые колонки
и техспек — пользовательская настройка представления, не изменение БД.

## Оценка текущего воплощения

- Mini App теперь показывает все 214 предложений, сгруппированных по
  позиции, даёт искать по поставщику и товару и скрывать техспек,
  подробные этапы и финансы. В исходной версии после 200 предложений
  остальные 14 незаметно исчезали.
- Схема хранит предложения отдельно от поставщиков, а наблюдения
  отдельно от предложений. Это позволяет сравнивать историю цены и
  достоверности. Для выбора нужны также нормализация упаковки/MOQ,
  сравнение полной цены и проверка каждого обязательного пункта техспека.
- Импортированная заявка не имеет `case_parse_versions` со статусом
  `applied`; прежняя команда подготовки поиска использует именно эту
  таблицу. Для неё добавлен запуск поиска отдельной позиции из Mini App.
  В проверке с откатом транзакции план для № 9 создал четыре ветки
  (своя база, 2ГИС, OLX, веб), каждая указала на правильный ID позиции,
  а заявка и очередь после отката остались без изменений. Живой запуск
  полного цикла ещё не выполнялся. Подробный техспек пока сверяется с
  найденными предложениями вручную.
- Закупка и приёмка подтверждаются отдельными событиями. В Mini App теперь
  доступны ввод приёмки, складского поступления, передачи заказчику,
  отказа, возврата и частичной отмены с количеством и причиной. Исторические
  пометки Notion по-прежнему видны отдельно от новых фактов.
- Общие расходы моделируются как план/факт с категориями и
  распределением по позициям. Сервер отвергает транзакцию, если сумма
  долей не равна расходу. Mini App позволяет выбрать позиции и способ
  распределения: поровну, по количеству или вручную.
- Исследовательский план для новых заявок содержит отдельный OLX-источник;
  2ГИС остаётся отдельной веткой. Браузерный контракт отсекает пустой
  прогон без посещённых страниц. Серверный Antigravity CLI успешно
  авторизуется через keyring после первоначального сообщения «not logged
  in»; прежний вывод о необходимости повторного входа был неверным.
  Диагностический прогон с лимитом 55 секунд завершился тайм-аутом после
  авторизации. Лимит рабочего адаптера — 240 секунд. Повторный поиск с
  этим лимитом показал CAPTCHA 2ГИС для IP сервера и тоже исчерпал время.
  После изменения браузерной инструкции повторная ветка завершилась
  явной ошибкой «ни одной просмотренной страницы» вскоре после CAPTCHA;
  бот не считает её пустой выдачей и не пытается пройти проверку.
  OLX в том же серверном браузере открыл поисковую выдачу и карточку
  товара. После настройки отдельной быстрой модели и нормализации пустого
  поля уверенности автоматическая ветка извлекла продавца, ID объявления,
  ID профиля, цену и MOQ. В проверке с откатом транзакции повторное
  сохранение найденного объявления нашло существующее предложение:
  число предложений по позиции осталось 6 до и после. Исходный лид был
  внесён отдельно по проверенному снимку страницы; проверка автоматической
  ветки не добавляла новых записей в рабочую базу.
- Отправка поставщикам через WhatsApp требует существующих approval и
  ограничений рассылки. OLX-чат как самостоятельный канал отправки пока
  не реализован; наличие публичного объявления само по себе не даёт
  разрешения или адреса для сообщения.

## Порядок завершения

1. Для 2ГИС решить доступ к официальному источнику: серверный браузер
   получает CAPTCHA. Для OLX проверить полный штатный цикл от кнопки
   поиска по импортированной позиции до результата в Mini App; план,
   извлечение и сохранение без дубля подтверждены с откатом транзакции.
2. Добавить прямую фиксацию закупки с документом, явный ввод замены после
   отказа и уточнение количественных правил для нескольких партий.
3. Добавить к новым событиям загрузку документа из Mini App и журнал
   изменений, видимый на карточке позиции.
4. Для предложения показать фасовку, MOQ, доступное количество,
   соответствие обязательным параметрам, документам и сроку; ранжировать
   по полной стоимости и уверенности, без автоматического выбора.
5. Разрешить доступ к общей заявке второму пользователю только после
   явной модели ролей и прав; сейчас Mini App показывает заявки владельца.
