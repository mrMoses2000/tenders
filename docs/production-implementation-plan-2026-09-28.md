# План доведения закупочного бота до рабочего релиза

Обновлено: 29.09.2026. Статус: **в работе; промышленная готовность не подтверждена**.
Этот файл — текущий чек-лист реализации. После каждого этапа менять статус,
вписывать фактическое подтверждение и следующий блокер. Подробная история
решений остаётся в `tender-agent-master-implementation-plan.md`.

## 0. Цель, границы и критерий «готово»

Оператор получает заявку с позициями и техспеками, запускает поиск по выбранному
городу, видит реальных продавцов и доказательства из 2ГИС, OLX и web,
согласует исходящие сообщения, получает ответы в WhatsApp, сравнивает
подтверждённые цены **соответствующего товара** с тендерной ценой, выбирает
поставщика, фиксирует закупку, фактическую доставку и приёмку, закрывает заявку.
В Mini App и Telegram видны статус каждой позиции и пять лучших сопоставимых
предложений. Каждое число и контакт ведут к источнику или сообщению.

Сейчас **не рассчитывать НДС и прогнозную логистику**. Цены сравниваются как
получены от продавца, без вычитания или добавления НДС. Расходы на доставку,
погрузку и прочее появляются только после ввода факта оператором; они
распределяются по указанным позициям и не подменяют цену предложения.

Релиз возможен после прохождения сценария на нескольких реальных сложных
позициях: карточка источника → реальный телефон → отправка WAHA с одобрением →
ответ → точная привязка к позиции → подтверждённые цена/количество/единица →
техническое решение → отчёт → закупка/доставка/приёмка/закрытие. Лид,
публичная цена, успешный тест или статус WAHA `WORKING` не заменяют этот опыт.

## 1. Архитектура и контракты

| Узел | Ответственность и единица развёртывания |
|---|---|
| Telegram bot | Приём документов/команд, точные одобрения, отчёт и статус. Отдельный systemd service. |
| Mini App | Авторизованный просмотр и ввод фактов. Локальный HTTP service за HTTPS-туннелем. |
| Worker | Задачи поиска, AGY, Codex browser fallback, обработка ответов, отчёты и outbox. Отдельный service. |
| WAHA webhook | Приём событий, строгая проверка и неизменяемый журнал. Отдельный service; WAHA в Docker. |
| PostgreSQL | Истина для заявок, позиций, требований, поставщиков, контактов, доказательств, предложений, диалогов, согласований, закупок, доставки и событий исполнения. |
| Файловое хранилище | Приватные исходные документы и версионированные отчёты по хешу. |

Основная связь: `customer → case → item → requirement`,
`item → offer → supplier/contact/location → source evidence/observations`,
`contact + case + item/offer target → conversation → immutable messages`,
`item → purchase/document → delivery run/items/payments → execution/acceptance → case closure`.
Второй товар в переписке с тем же контактом получает отдельную цель; ответ без
однозначной цели отправляется оператору на разбор, а не создаёт цену сам.

Внешние эффекты только через отдельные адаптеры и одобряемый outbox. Задачи
имеют idempotency key, lease, ограниченные повторы и dead-letter; повтор
поиска не дублирует карточку. Неполный результат остаётся явно неполным.
Секреты Telegram, WAHA, БД и браузера вне AGY prompt и логов. В health
нужны БД, очередь, outbox, сервисы и доступность Mini App; ошибки связывать
с заявкой/позицией/поиском. Нужны backup/restore и процедура разбора
незавершённой отправки после падения.
